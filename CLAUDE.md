# case-service: project guide for Claude

GrowerCare field cases (ADR-017: its own repository): cases on 128 shard schemas, workflow, comments, partner sharing, SLA timers, routing and attachments. It consumes IAM grant events and publishes case events via the outbox.

## Where things are
| Topic | Location |
|---|---|
| Feature specs (rules, examples, traceability) | `docs/specs/case/01–05` |
| Database schema | `docs/schema.md`; migrations `src/main/resources/db/case/{common,shard,dev-seed}` |
| OpenAPI contract | `contracts/case-service.openapi.json` (regenerated by tests; drift fails CI) |
| Shared libraries | `com.growercare:gc-*` 1.0.0 (growercare-platform-libs) |
| Cross-cutting specs, ADRs | growercare repository |

## Conventions
1. **Authorization:** via gc-security (role + geo + BU scope). An out-of-scope resource returns **404**. Never trust client-supplied country or shard.
2. **IDs:** generated by Postgres per shard. Route by decoding them. Serialize IDs as **strings** in JSON.
3. **Events only through the outbox.** Consumers are idempotent (`msg.inbox`).
4. **Country differences** go into reference data or compliance packs, never `if (country == …)`.
5. **Redis is never a system of record.**
6. **No ORM:** named SQL via `JdbcClient` (ADR-013).
7. **Migrations** are expand → migrate → contract across all shard schemas. The first statement of each shard migration takes the advisory lock.
8. **Configuration only from environment variables** (SPEC-PLAT-06):
   - every variable is documented in `.env.example`;
   - `ConfigurationHygieneTest` guards it;
   - IAM is reached only over the network (`IAM_BASE_URL`).
9. **Spec-driven development:** spec → parameterized test rows named after spec example IDs → code → green.
10. **Reporting:** run `mvn -B verify` before claiming success.
11. **Git workflow:**
    - never commit to `main`;
    - branch `<type>/<name>`;
    - PR body with `Spec: docs/specs/...`;
    - squash-merge when CI, policy and Claude review are green.
